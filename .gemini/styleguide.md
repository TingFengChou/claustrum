# claustrum — Gemini Code Assist 審查規範

以繁體中文審查。只列具體問題(附檔名與簡短引用),乾淨的檔案不必提。最後給一行結論:
LGTM / minor comments / needs work。**審查為建議;合併由維護者查證事實後決定**(見 `docs/DEVELOPMENT.md`)。

依序聚焦:

## 1. 正確性與邊界情況
可能造成錯誤描述、漏報/誤報安全告警、或崩潰之處(空值、邊界、資源釋放、執行緒、OOM/重入)。

## 2. 專案不變式(勿讓其退步)
- **Actant 是角色槽位,絕非身分**;不做人臉/身分/年齡辨識(例:寫「一人」而非「長者」)。
- **`risk.level != none` 必須有畫面內可見證據**;偵測/告警不臆測(誤報是頭號敵人)。
- **L1 只客觀描述看得到的**;風險/事件判斷屬 L2。
- **novelty 由管線計算,非模型自我回報。**
- **dataclass 與 JSON Schema 一致**(schemas/ 為跨語言單一真實來源)。
- **影格/像素只在裝置端流動、用完即刪**;只有文字描述/事件可外傳(隱私/PDPA)。
- 藥品/醫療相關必須有免責且不臆測。

## 3. 可測試性
新邏輯是否可不靠硬體單元測試(相依置於介面之後、副作用集中邊界)?有無隨附測試?

## 4. 設計文件同步
動到模組是否更新其 `docs/design/<module>` 的 SA/SD?里程碑是否同步 README/ROADMAP?過時文件視為 bug。

## 5. 簡潔、可讀、與周邊程式一致
命名、風格與既有程式一致;避免不必要複雜度。
