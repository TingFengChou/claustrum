# events(時間性事件引擎)— 系統分析(SA)

**狀態:** draft(規劃)· **最後更新:** 2026-08-06 · **負責人:** claustrum
**實作:** [`SD.md`](SD.md)

## 1. 目的與範圍

一個**時間性事件偵測引擎**:把「帶時間戳的觀察串流」串連起來,偵測**單幀看不出、必須跨時間才成立**的事件——例如**跌倒**、**出門**、**暴力衝突**。

單張畫面只能說「有人躺著」;要判斷「他**跌倒**了(從站立在數秒內倒地且未起身)」或「他**出門**了(在門口出現後消失)」,必須把一連串帶時間戳的觀察連起來看。這個引擎就是做這件事——它是 L1(感知/影像描述)與 L2(告警)之間的**時間推理層**。

範圍內:觀察串流的時間窗維護、可插拔的事件偵測器、結構化 Event 輸出。
範圍外:單幀感知(L1 caption / pose / 音訊本身)、告警投遞通道與 UI(L2 消費 Event)。

## 2. 參與者與情境

- **L1 感知** — 產生 Kineme / 即時描述(每筆帶 `ts`)。這是引擎的主要輸入串流。
- **L0 訊號** — pose landmarks、音訊事件(尖叫/衝突聲),附到觀察上作為額外證據。
- **事件引擎(本模組)** — 消費觀察、輸出 Event。
- **L2 告警** — 消費 Event,套用抑制後通知保全 / 觸發聲光告警。

## 3. 功能需求

- **FR-1** 維護一個**滾動時間窗**的觀察串流(`Observation`:`ts` + 描述/動作 + actants + 可選 pose/音訊訊號 + confidence),過期即淘汰。
- **FR-2** 以**可插拔的偵測器(detector)** 在時間窗上偵測事件;每個 detector 是對觀察序列的**狀態機 / 謂詞**。
- **FR-3** 產生結構化 `Event`(type、`ts_start`、`ts_end`、confidence、`evidence`=觀察 ids、summary)。
- **FR-4** 內建偵測器:**FallDetector(跌倒)**、**LeaveDetector(出門)**、**ViolenceDetector(暴力,音+視融合)**。
- **FR-5** Event 輸出接到 L2 告警(含去重 / 速率限制 / 冷卻 / 人工確認,ADR-0006)。

## 4. 非功能需求

- **NFR-1 即時。** 事件從發生到輸出 p95 < 5 s(對齊關鍵指標)。
- **NFR-2 Edge。** 於裝置端運行,不依賴雲端。
- **NFR-3 抗雜訊 / 抗幻覺。** 小模型描述有雜訊;事件需**多幀或多訊號佐證**、去抖後才成立;`unclear`/低信心觀察不推進狀態機。
- **NFR-4 可測試。** 引擎核心與每個 detector 皆為**純函式 / 純狀態機**,以合成觀察序列單元測試,不需硬體。
- **NFR-5 隱私。** 只消費 Kineme / 訊號(文字與座標),**不碰原始影格**;影格留在原生層。

## 5. 領域模型

- **Observation** — 一筆帶時間戳的觀察(視覺來源即 `Kineme`;可附 pose、audio_events)。
- **Event** — 由觀察序列偵測出的事件(需要新的 `schemas/event.schema.json` 契約)。

## 6. 限制與假設

- 觀察串流的品質受 L1 模型能力限制(SmolVLM 描述較粗;Gemma 較準但較慢)→ detector 設計要能容忍雜訊、以狀態轉移與時間門檻為主,而非單筆描述字面。
- pose / 音訊訊號的取得(L0)為前置相依;初版可先只用視覺描述 + 簡單 pose。

## 7. 驗收標準

- 合成序列「站立 → 數秒內倒地 → 未起身」→ FallDetector 觸發一個 fall Event;「倒地後很快站起」→ 不觸發。
- 「門口出現 → 消失 > T 秒」→ LeaveDetector 觸發 leave Event。
- 無事件 / 抖動序列(偶發一兩幀雜訊)→ **不誤觸發**。
- 以上皆為 detector 的單元測試(純函式)。

## 8. 未解問題

- Observation 如何攜帶 pose / 音訊訊號(schema 擴充 vs 平行串流)。
- detector 用規則式狀態機起步;日後是否引入輕量學習式判斷。
- 各事件的時間門檻與抑制參數(需以真實資料調校)。
